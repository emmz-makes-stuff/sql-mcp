# §14 Review fixes: errors that escape — done

<!-- Section: 14 · Tasks: 14.1–14.3 (14.4 landed in §13) · Base: 062caa6 -->

What landed:
- **14.1, escaped exceptions are audited.**
  - `ToolPipeline.QueryAsync` now catches any non-cancellation exception that escapes `IQueryExecutor`. It audits
    a `failed` event (kind `other`) and returns `query failed: <exception message>`.
  - The guard is in the pipeline, not the executor, so it covers every engine.
  - `FakeExecutor.Throws` drives the test.
- **14.2, cancel before dispose.**
  - `BufferAsync` tracks `completed`. On any early exit, a cap or an exception, `CloseReaderAsync` cancels the
    command before disposing the reader.
  - The cancel path now also swallows `InvalidOperationException`, as well as `SqlException`.
- **14.3, limits.**
  - The schema gives `maxRows`, `pageSize` and `timeoutSeconds` a `maximum` of Int32.MaxValue, and `maxBytes` one
    of Int64.MaxValue. A value that's too large is a schema error naming the file and JSON path.
  - The loader reads whole-number decimals (`100.0`, `1e6`) through `GetDecimal`, because JSON Schema counts them
    as integers.
  - `10.5` was already a schema error.

Emmz confirmed the three choices where the build differs from the task text:
1. The guard is in the pipeline, not the executor, and the agent sees the exception message.
2. 14.2 can't be shown to matter for cancellation (see the gotcha below). The fix stays as a safeguard, and the
   test stays as a check that a cancel returns quickly.
3. Whole-number decimals are accepted, not rejected.

Gotchas:
- **Finding 5's scenario doesn't happen.** I ran the new itest `A_cancelled_query_returns_promptly` with the fix
  switched off, and it still passed: SqlClient cancels the command itself when the token fires. The drain only
  follows a non-cancellation exception part-way through, such as a conversion error, and SQL can't trigger that.
- xUnit1069: a `[Fact(Timeout = …)]` test must use `TestContext.Current.CancellationToken` directly. The class's
  `Cancel` property doesn't count.
- `$TMPDIR` is a different directory sandboxed and unsandboxed. A backup copied there during the unsandboxed
  mutation run wasn't visible to the next, sandboxed command.
