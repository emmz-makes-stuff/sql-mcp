- **8.1 One connect helper.** `Introspection/SqlServer/CatalogConnection.cs` takes the effective connection string,
  opens asynchronously, runs the work and maps failures: an invalid string or failed open → `Connection`; a
  `SqlException` anywhere in the chain → `Timeout` (-2) or `Sql`; a caller's `classify` hook covers the rest
  (`UnresolvedName` for the reader, Smo/Sfc → `Other` for the generator). Messages are `"{activity} timed out after
  … so it was cancelled.{advice}"` and `"{activity} failed: …"`, with activity set to `reading the catalog` or `scripting`, so
  the wording is unchanged. The generator now opens through the helper and only goes to `Task.Run` for the SMO work.
  The only `-2` left is `SqlServerQueryExecutor.TimeoutErrorNumber`, now `internal` (Emmz: one constant everywhere).
- **8.2 Chosen trigger through its parent.** `ObjectSummary` gains `Parent` (init) and `ToItem()`. Resolution fills
  `Parent` for a DML trigger, and `SmoScriptGenerator.Chosen` looks the trigger up as `Tables[p]`/`Views[p].Triggers[name]`.
  A trigger without a parent fails as not found (`Other`). **Whole database: no code change.** A temporary probe
  (a SqlClient DiagnosticListener on a 40-table database, deleted before the commit) counted 209 commands. Trigger
  enumeration was 3 queries: every table's triggers (no WHERE), every view's, and the database triggers. That comes
  from the existing `PrefetchObjects` and `SetDefaultInitFields`. The only per-trigger queries are SMO scripting each
  trigger. Emmz agreed to tick 8.2 on this evidence.
- **8.3 Chosen inventory from resolution.** `ICatalogReader.ResolveAsync` returns `Resolution(Objects, Inventory)`.
  The inventory is the chosen objects plus the DML triggers of the chosen tables and views, with encryption and
  parents. That takes one extra query, `ChildTriggersSql`, with ids matched by `CHARINDEX` because OPENJSON needs
  compatibility level 130. `DatabaseScripter` calls `InventoryAsync` only for a whole database.
  `Completeness.Narrowed` and its unit test are gone. The new `EntriesCte` (objects plus `encrypted`) and `ParentJoin`
  are shared by `InventorySql`, `ResolveSql` and `ChildTriggersSql`.
  - Gotcha: `sys.objects.type` is `char(2)`, so `CAST(o.type AS varchar(2))` gave `"U "`. `ObjectsCte` now uses `RTRIM`.
  - Emmz accepted that the chosen inventory is sorted ordinally (type, schema, name), not by the database's collation.
- **8.4** The `objects` items schema is `anyOf` with no `additionalProperties`. `ToolCatalogTests` asserts that there
  is no `oneOf` and no `additionalProperties`. The human-verification line in `tasks.md` is updated.
