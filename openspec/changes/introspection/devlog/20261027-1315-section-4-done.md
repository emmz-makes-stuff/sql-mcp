# §4 done: script generation and completeness

Built `IScriptGenerator`; `Completeness.cs` (`CatalogItem`, `CatalogItemTypes`, `InventoryClass`, `InventoryItem`,
`OmittedItem`, `Completeness.Omitted`); `ICatalogReader.InventoryAsync` and its query in `SqlServerCatalogReader`;
`SmoScriptGenerator` (whole database and chosen objects); and the `EngineServices.ScriptGenerator` slot, wired in

Emmz's answers (2026-10-27, asked during the section):
- **Shape:** `CatalogItem(Schema?, Name, Type)` with `Type` a wire string, not `ObjectType`, so the kinds agents can't
  list don't leak into `list_objects`' type filter. The `EngineServices` slot came with `SmoScriptGenerator` (4.3),
  not in 4.1.
- **Wire names for the other kinds** are snake_case catalog names: `schema`, `partition_function`, `partition_scheme`,
  `xml_schema_collection`, `assembly`, `fulltext_catalog`, `user`, `role`, `application_role`, `permissions`,
  `certificate`, `asymmetric_key`, `symmetric_key`, `database_scoped_credential`. Any other top-level user object
  (rule, standalone default, service queue, external table…) is `LOWER(type_desc)`: `rule`, `default_constraint`, …
- **A chosen object that can't be scripted** (an encrypted procedure) doesn't fail the call. The file is written, and
  §5.3 runs `Completeness` with the inventory narrowed to the chosen set, so the omitted list names it as `encrypted`.
  The generator just leaves it out (`Chosen_encrypted_procedure_is_left_out`).
- **User schemas are inventoried and scripted** (ids 5–16383, no `AUTHORIZATION`). Design I5's list didn't name them,
  but the round trip needs them.
- **A catch-all for other top-level `sys.objects`**, so anything SMO skips shows as "not scripted by the generator".
- **Permissions: one omitted entry per grantee**, `{schema: null, name: <principal>, type: "permissions", reason:
  "security principal"}`, for the spec's "users, roles and permissions… named in the list". The defaults every
  database has don't count: a user's `CONNECT`, public's `SELECT` on system objects, and public's two
  `VIEW ANY COLUMN … KEY DEFINITION` grants.
- **The as-built choices below were OK'd before the commit.**

SMO facts found by probing (the generator's remarks hold the same list):
- `DiscoverDependencies` refuses schemas. So the script has three parts: schemas and full-text catalogs; then the
  walk; then DML triggers.
- **An encrypted DML trigger fails its whole table when `ScriptingOptions.Triggers` is on.** And a trigger URN inside
  the walk fails to script ("no collection of Table objects that is a child of Table"). So `Triggers` is off, and the
  non-encrypted DML triggers are scripted on their own, last, with `EnumScriptWithList`. That's a departure from I5.
- `EnumScriptWithList` never yields `GO`, whatever `ScriptBatchTerminator` says, so that option is dropped and the
  generator writes `GO` after every batch.
- The walk adds parents that weren't asked for (types, sequences, the partition scheme) and repeats some nodes. It is
  filtered back to the candidates, first place kept. That one filter serves the whole database (it drops the
  encrypted parents) and chosen objects (4.4).
- **SMO creates every table, then adds the FKs with `ALTER TABLE … ADD CONSTRAINT`.** So the 4.3 test checks that
  each FK is added after both its tables, not that the target table is created first. Chosen `orders` and
  `order_lines` still come out with `orders` first.
- `Database.EnumObjects` mixes in system objects (broker queues, `Microsoft.SqlServer.Types`), so the candidates come
  from SMO's collections, filtered by `IsSystemObject`, with `SetDefaultInitFields`/`PrefetchObjects` so that each
  collection is one query.

Other decisions:
- **Failures:** an innermost `SqlException` -2 is `Timeout`, any other `SqlException` is `Sql`, and an SMO or SFC
  exception is `Other`, with the whole message chain, since SMO wraps the cause in "Script failed for Server…".
  Connection failures are classified before SMO starts, as in the reader.
- **An object the reader resolved but SMO can't find** (dropped in between) is an `Other` failure, not a silent gap.
- **Inventory order** is `class, type, schema, name`, and `Completeness.Omitted` keeps it.
- **Test infrastructure:** the SMO tests made two executor tests flaky. One measures process-wide allocations; the
  other checks a session the server ends asynchronously. `SqlServerQueryExecutorTests` is now a non-parallel
  collection (`RunsAlone`), and `Connection_released_before_paging` waits up to 2 s for the session to go.

Known gaps: an encrypted *database* DDL trigger reads as unencrypted in the inventory (the §3 `OBJECTPROPERTY` gap),
so it would be omitted as "not scripted by the generator". CLR objects, full-text catalogs and the generator's
timeout path aren't tested, because the container has no CLR or full-text and there's no way to force an SMO timeout.
