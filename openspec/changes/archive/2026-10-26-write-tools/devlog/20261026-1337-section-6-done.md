# §6 done: tools, responses and audit

<!-- Base 68d5004 · gates green -->

What landed (design W7, W8):
- **`ToolPipeline.RunAsync(tool, category, mode, database, sql, ct)`:**
  - `QueryAsync`, `CommandAsync`, `DdlAsync` and `ExecuteAsync` are one-line wrappers over it.
  - The group comes from `CategoryGroups[category]`, so there's no separate group parameter, unlike W7's sketch.
  - Audit order is unchanged for every tool.
  - An escaping exception reads "`{tool} failed: … `". For a write it adds `WriteMessages.NothingCommitted`.
- **`WriteMessages.NothingCommitted`** (in `IQueryExecutor.cs`) is the one copy of that sentence. The executor and
  the pipeline both use it.
- **Audit:**
  - `ExecutedEvent` gains `RowsAffected` (`IReadOnlyList<int>?`, null for reads, so it's omitted).
  - `FailedEvent` gains the init properties `Cap` and `Affected`, mapped from `QueryFailed`.
  - `AuditEventShapeTests` allows `RowsAffected`, `Cap` and `Affected` and the types `long?` and
    `IReadOnlyList<int>`. `OneOfEach` has a write example of each event (hence the `.Distinct()`).
- **Response:**
  - A write with no result sets returns `WriteResponse` `{"committed":true,"rows_affected":[3,5]}`, with no
    pages and no handle.
  - With result sets, `PageResponse.First(...) with { Committed, RowsAffected }`. Later pages don't repeat
    them.
- **Catalog:**
  - The write tools are registered per group, only when that group is allowed somewhere.
  - `Create(..., readOnly: false)` sets not read-only, destructive, `Idempotent = false`, and not open-world.
    Query's annotations are unchanged (`Idempotent` stays unset).
  - Paging is offered when query, command or execute is; ddl alone offers none.
  - Tool order: list_databases, query, command, ddl, execute, next_page, abandon.
- **Descriptions:**
  - `ToolDescriptions.CommandGuidance`, `DdlGuidance` and `ExecuteGuidance` each add the shared `WriteGuidance`
    (all or nothing, narrow changes, over the cap runs in full first, count with query first, the names rule,
    the response shape).
  - `ToolDescriptions.Write(...)` appends "Default affected-rows cap: N rows per batch.", plus "Databases with
    another cap: …", listing only databases where the group is allowed.
  - The `execute` description carries the SELECT-counts ruling and NOCOUNT.
  - The `next_page` and `abandon` descriptions and their handle parameter now name all three tools.
- **README:**
  - a new `## Tools` section: table, writes all or nothing, the cap, the WHERE and names rules, what ddl and
    execute refuse, and the `timeoutSeconds` callout;
  - the summary bullet mentions writes;
  - the stale "this release has the query tool" paragraph is gone;
  - the audit paragraph explains `executed` and `failed` for writes.
- **Tests:**
  - `ToolPipelineTests` gains: statement of another category ×3, group denied ×3, write mode ×3, committed
    write, a write paged like a query, a read with no `rows_affected`, the cap rollback, an escaping exception,
    and a committed but unlogged write. `FakeExecutor.During` exists for that last one.
  - `ToolCatalogTests` gains 8 tests, including "Client sees a destructive tool". "No database allows command"
    already existed.

Emmz approved, as built (2026-10-26):
- After a commit, if the audit write fails, the error is "audit log unavailable: the batch was committed, … Don't
  run it again." instead of the plain unavailable message. No rows are returned.
- `executed.rows` for a write is the rows *returned*, and `rows_affected` is separate.
- The names rule is in every write description. `next_page` warns against rerunning a write. ddl alone has no
  paging.
- A write that can't connect keeps "could not connect: …", with no "nothing was committed", because nothing ran.

Not changed: `openspec/specs/*` still has the old "no command tool" scenario. The delta specs replace it at archive.
