# Handoff: §7 landed; §8 planned, with 8.4 added for client schema support

After §7's commit (`bb2dbd2`), a side agent warned that `script_database`'s `objects` items schema (`oneOf` with
`additionalProperties: false`, from 7.3) may be handled badly, or rejected, by model APIs with partial JSON Schema
support, Gemini especially. Nobody has confirmed that a current client breaks on it.

Emmz's ruling (2026-10-28): **switch to `anyOf` now and drop `additionalProperties`** from the schema. The two
branches never overlap, since one is a string and the other an object, so `anyOf` means the same. The server still
refuses extra keys in `ParseObjectsEntry`. This is task 8.4. The human-verification line in `tasks.md` "Workflow
follow-up" now also asks for the server to be loaded in Claude Code, Gemini, Codex and OpenCode, with a
`script_database` call mixing a plain name and a `{name, type}` entry. 8.4 updates that line to say `anyOf`.
