The last section from the `code-review` of §7–§8.

- **10.1** `ResolveAllAsync` resolves every name in one query. `NameList` joins each name's schema, name and type
  (empty when not given) with U+001F, and ends each name with U+001E. `ResolveSql` splits that list with a
  recursive CTE (`split`, then `requested`) under `OPTION (MAXRECURSION 0)`, and tags each candidate with its
  name's 1-based position. The separators are found with `COLLATE Latin1_General_BIN2`, because some collations
  ignore control characters. The match itself stays in the database collation. `NameResolution.Problem` still runs
  once per name, in the order given. An empty name list skips the query.
  - `ObjectName.TryParse` refuses a name holding either separator: "`'<text>' holds a control character (U+001E or
    U+001F), which sql-mcp can't look up.`" `ObjectName.FieldSeparator` and `RecordSeparator` hold the two characters.
  - New itests: 210 names in order, with duplicates (past the default recursion limit of 100); 153 names with one
    ambiguous; and a resolve at compatibility level 120 in `CompatibilityLevelTests`. There's also a unit test for
    the refusal.
- **10.2** A DML trigger's parent is now a `TriggerParent(string Schema, string Name, ObjectType Type)` (in
  `CatalogModel.cs`), not a `CatalogItem`, on both `ObjectSummary.Parent` and `InventoryItem.Parent`.
  `SmoScriptGenerator.Owner` switches on `{ Type: ObjectType.Table }` and `{ Type: ObjectType.View }`.
- **10.3** `IntrospectionCall<T>` is an abstract record with a private constructor and two cases, `Ready(Request,
  Read)` and `Refused(Error)`. `RunIntrospectionAsync` returns a refusal's error, then deconstructs `Ready`.
  `call.Error!` is gone. C# can't infer `T` through the two subtypes, so the three tools now call
  `RunIntrospectionAsync<ObjectList>`, `<ObjectDetails>` and `<ScriptResult>`.

- Only the two separators are refused, with the wording above.
- There's no cap on how many names one call resolves; the command timeout bounds it.
