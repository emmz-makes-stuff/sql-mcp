- **6.1, bug:** `list_objects`' type filter used `STRING_SPLIT`, which a database below compatibility level 130
  doesn't have (error 208). It is now `CHARINDEX(',' + type + ',', ',' + @types + ',') > 0`. The new
  `CompatibilityLevelTests` runs list (with types), inventory and describe on a level-120 database of its own. It
  failed before the fix (list returned `CatalogFailed`) and passes after it. No other compat-gated function
  (`STRING_SPLIT`, `OPENJSON`, `STRING_AGG`, `TRIM`, `CONCAT_WS`, `IIF`) appears in `src/`.
- **6.2:** `design.md` now matches what was built:
  - I3: the `clr` reason, a database trigger reporting `no permission`, and no `schema` key for database triggers;
  - I4: the `CHARINDEX` note;
  - I5: `Triggers` and `ScriptBatchTerminator` off and why, the three-part script, and chosen objects taking their
    triggers;
  - I6: the directory mirroring the audit log, and the per-suffix temp-file reservation;
  - I7: `Kind`, `ErrorNumber` and `UnresolvedName` in place of `Error`.

  ADR-0003's "Gate" line is left as it was: it's history.
- **6.3:** fixed the "write tool)'s" doc comment in `ToolCatalog.cs`, and deleted `SmoSpikeTests` (§1's gate). The
  round-trip and `SmoScriptGeneratorTests` cover the same types.
- **6.4:** the new `CatalogTimeoutTests` covers a real catalog timeout. Another connection holds
  `ALTER TABLE … ADD` uncommitted, so `list_objects`' read of that table blocks on the schema-modification lock
  until the 1-second timeout. The test asserts `Timeout`, error -2 and the exact message. It's deterministic
  because the lock is held until the test rolls back. The `git status` half of 6.4 was already covered by
  `AuditGitIgnoreTests.Project_initialised_before_this_change_does_not_show_the_script`, which I missed in the
  review, so nothing was added for it.
