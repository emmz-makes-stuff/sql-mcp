§9 and §10 come from the `code-review` of §7–§8 (`d36a202..HEAD`, medium). It made 9 findings. Emmz took 1, 2, 4,
5, 6, 8 and 9. She dropped 3 (encrypted database trigger without VIEW DEFINITION, accepted in §7.6) and 7 (ordinal

- **9.1** `SmoScriptGenerator.Chosen` removes duplicate URNs from its trigger list, so a trigger named alongside its
  table is scripted, and counted, once. An itest replays that script in a fresh database.
- **9.2** A chosen trigger on an encrypted view is left out, through the new `Owner(database, trigger)` helper, which
  returns the parent's triggers and whether it is an encrypted view. Resolution's inventory names it `on an encrypted
  view`. To make that possible, `InventoryItem` gained `ParentEncrypted`, filled from `p.encrypted`: `ParentJoin` and
  `ChildTriggersSql` now join `entries AS p` rather than `objects AS p`. `Completeness.Reason` uses that flag and no
  longer looks the parent up in an encrypted set, so the reason holds when the view isn't in the inventory. A
  whole-database script behaves the same.
- **9.3** A DML trigger with no resolvable parent fails (`Other`) with "`'dbo.x' (trigger) is on a table or view that
  sql-mcp doesn't list, such as one marked as shipped by Microsoft, so it can't be scripted.`" A parent that has
  vanished still gets "was not found when scripting began".
- **9.4** `NameResolution` adds, for mixed schemas where one schema holds an object and a type of that name: "`In dbo,
  an object and a type share the name, so give its type too, such as table_type.`"

Emmz approved all three choices and the wording, 2026-10-28. The README (chosen objects) and `design.md` I5 are
updated.
