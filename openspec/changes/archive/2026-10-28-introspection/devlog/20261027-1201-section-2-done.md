# §2 done: catalog model, SQL Server reader, list_objects

Built `Introspection/` (`CatalogModel.cs`, `ICatalogReader.cs`, `Glob.cs`, `SqlServer/SqlServerCatalogReader.cs`),
`ToolPipeline.RunIntrospectionAsync`, the `list_objects` tool and its response, and the new `IntrospectionEvent`.

Decisions (where this departs from tasks.md / design):
- **Types are added in the section that first uses them.** 2.1 named `ObjectName`, `ObjectDetails` and the
  `ScriptGenerator` slot in `EngineServices`. They were left out, because they would have landed as unused
  types or stub methods, which the self-review rule forbids. `ObjectName` and `ObjectDetails` come with §3, and
  `IScriptGenerator` with its `EngineServices` slot with §4. `ICatalogReader` gains `ResolveAsync`/`DescribeAsync`
  in §3 and `InventoryAsync` in §4.
- **`IntrospectionEvent` has no `Error` text** (design I7 said `Error`). It is
  `(Tool, Database, Request, DurationMs, Succeeded)` plus `Kind` (`FailureKind?`) and `ErrorNumber`. Reason: as with
  `FailedEvent`, SQL Server message text can echo values, so it is never logged. `Request` is
  `IReadOnlyList<string>`: the filters as `schema=…`, `types=a,b`, `pattern=…`, and in §3/§5 the object names.
  `AuditEventShapeTests` now allows `Request`, `Succeeded` and `FailureKind?`. The unused `Target` field is gone.
- **DB-level triggers have no `schema` key** in the JSON (null is left out by `ToolResult.Json`), rather than
  `schema: null` as design I3 put it. The tool description doesn't promise a key.
- **The executor's connection-string builder** became `SqlServerQueryExecutor.EffectiveConnectionString`, shared
  with the reader, so both connect unpooled with `Application Name=sql-mcp`.
- **The type filter is validated before the database lookup**, like an argument error. It is not audited, the same
  way an unknown database identifier is not. Blank `schema`/`pattern` strings count as "not given".
- **Catalog reads use the database's row cap (`maxRows`)** as the `list_objects` cap, as the spec says. There is
  no new limit.
- **Tests that list default tools** now expect `list_objects`, because introspection is allowed by default. Three
  catalog tests about query and paging now deny `introspection` too, to keep their intent. `ServeTests` (the real
  MCP client, which sorts tools by name) were updated the same way.

Test infrastructure for §3–§5:
- `SqlServerFixture.CreateDatabaseAsync(name, collation?)` and the static `RunScriptAsync(connectionString, script)`,
  which splits on `GO` lines.
- `Introspection/seed.sql` holds every object type, plus an encrypted proc (`dbo.secret_report`), a user
  (`app_reader`), a DB DDL trigger (`audit_ddl`), a temporal table (`dbo.prices` with `dbo.prices_history`), a
  partitioned table (`dbo.events` on `ps_events`), the ambiguous `dbo.orders`/`archive.orders` pair, and
  `dbo.Order_Archive` for case tests. `dbo.users` has 3 rows.
- `SeededDatabases` is an `IClassFixture` that creates `seeded_<rand>` and `seeded_cs_<rand>`
  (`Latin1_General_100_CS_AS`) for each test class. A class fixture taking the assembly fixture in its constructor
  works in xunit v3.
- `FakeCatalogReader` is in `tests/SqlMcp.Tests/Mcp/SessionBuilder.cs`. Extend it in §3 with Resolve/Describe outcomes.

Self-review: nothing to fix. One known gap: the reader's real timeout path isn't exercised against SQL Server,
because a catalog read can't be made slow reliably. The pipeline timeout handling is tested with the fake.
