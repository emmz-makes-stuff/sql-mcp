# §13 Review fixes: project-only databases need approval — done

<!-- Section: 13 · Tasks: 13.1–13.2, plus 14.4 · Base: 86646f3 -->

Why: `code-review` finding 1. An unapproved, checked-in project config could define a database whose connection
string reads `${env:…}` secrets, and the first `query` would send them to any host. The decision, and why
approval is per database, are in `20261025-2140-decision-review-fix-sections.md`.

What landed:
- **`ProjectApproval`** (new, `Permissions/`) holds `FileApproved` (the whole file's hash, which governs the grant
  and limit widenings) and `Databases` (identifier → SHA-256 of the raw connection string, before substitution).
  - `Of(project)` is the approval of the file as it stands.
  - `Covers(entry)` checks one database.
- **`ApprovalStore`:**
  - `Read(ConfigFile?)` replaces `IsApproved`, and `Approve(ConfigFile)` replaces `Approve(path, sha)`.
  - `approvals.json` entries gain `databases: { id: { sha256 } }`.
  - A damaged or missing store still gives `None`.
- **`PermissionResolver.Resolve(user, project, ProjectApproval)`:**
  - What happens to an unapproved project-only database:
    - `ConnectionString = null`;
    - the reason is `ApprovalMessages.NotApproved(AddsDatabase)`, plus `" Also: <original reason>"` when there
      already was one;
    - `UnapprovedWidenings` starts with `"adds this database"`.
  - Because of that last point, `list_databases`, `config show` and the warnings after config edits all report it
    with no code of their own.
  - Unparseable entries are unavailable anyway, so they're left alone.
- **`approve`:**
  - The diff compares what is approved now with what approving would give. Its line for an added database is
    `id: adds this database, reading ${env:X}` (variable names only).
  - It pairs databases **by position**, not by identifier. That fixes 14.4, the crash on two `(invalid)` entries,
    so 14.4 is ticked here, with its test.
  - "Already approved" is now just an empty diff with the file approved.
- **Spec:** "Project adds a database" now requires approval. New requirement "Project-only databases require
  approval", with four scenarios. D4 is updated, including the rejected whole-file option. The README quick start
  now runs `sql-mcp approve` after `db add`.
- `ServeTests` (itests) now approve their project config in setup, standing in for the person.

Emmz confirmed all seven of my own choices before the commit:
1. Both reasons are shown together.
2. A changed string reads as "adds this database".
3. `approve` lists no grants for an added database.
4. The `query` tool is still offered when only unapproved databases allow `query`.
5. There is no migration for an `approvals.json` that has no `databases` key.
6. 14.4 lands in §13.
7. A hash is stored for every database in the file.
