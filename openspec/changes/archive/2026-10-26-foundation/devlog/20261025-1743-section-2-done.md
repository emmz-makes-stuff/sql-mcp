The answers to the shape questions are in `20261025-1735-decision-config-shape.md`.

What landed (all in `src/SqlMcp/Configuration/`, plus `Permissions/ToolGroup.cs`):
- `ToolGroup` is defined here, ahead of §3, because the config model needs it. §3.1 builds resolution on it and
  doesn't redefine it.
- `ConfigLoader.Parse/Load` → `ConfigFile(Path, Defaults, Databases)`. `DatabaseEntry` holds `Location`
  (`databases[N]`), `Identifier`, the raw and the substituted connection string, and `UnavailableReason`.
  Its `ToString()` is overridden, because the default record printer would leak the connection string.
- `ConfigPaths.Create(isWindows, home, appData, cwd, projectDir)` is the testable form, and `ForCurrentUser`
  the real one. `Approvals` (next to the user config) is ready for §3.2.
- `DiscoveredConfig.NoDatabasesMessage` and `DatabaseIdentity.UnknownIdentifierMessage/Normalise` are ready for
  §7 (`list_databases`, tool-call lookup). Tool-call identifiers are trimmed and lower-cased before matching.

Decisions:
- **Env substitution is per keyword value**, through `DbConnectionStringBuilder`, so a value containing `;` can't
  inject `Server=`. This has a test.
- **The masker works on the raw string.** It masks literal `Password`/`PWD` and keeps `${env:NAME}` visible,
  since that names a variable rather than holding a secret.
- **Schema errors never print values**, except the string that failed an `enum` (a group or engine name). A
  mistyped property could hold a connection string.
- **Two malformed connection strings aren't "duplicates":** the `(invalid)` placeholder is excluded from the
  duplicate check.
- **The schema has no `$id`.** I had added a GitHub URL, but the org and name aren't decided until 9.1. Open: the
  `$schema` URL that `init` (§8.1) writes depends on that too.
- **`System.Security.Cryptography.Pkcs` is pinned to 10.0.14** (central transitive pinning). SqlClient 7.1.1 pulls
  in 9.0.18, which has GHSA-2fmv-rv2c-59x7 and GHSA-846f-f764-76mx; NU1902/NU1903 are errors here.
- The `.editorconfig` naming now has PascalCase rules for private `const` and `static readonly` fields. The
  `_camelCase` rule had caught those too, which failed `format`.

Gotchas:
- JsonSchema.Net 9.x `List` output adds summary errors for applicator keywords (`properties`, `items`,
  `additionalProperties`, `$ref`), which are skipped. A property rejected by `additionalProperties: false` is
  reported with an **empty keyword**, at an evaluation path ending in `/additionalProperties`. A test pins the
  exact output lines.
- `dotnet pack` puts `schema/config.schema.json` and `README.md` in the nupkg (checked by hand).

Self-review against the configuration spec: every requirement owned by §2 is covered. The layering and approval
requirements belong to §3. "Calls against it fail" and "list_databases" belong to §7.
