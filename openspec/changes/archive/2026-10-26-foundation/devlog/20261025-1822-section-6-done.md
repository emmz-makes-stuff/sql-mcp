# §6 Query execution done

<!-- Section: 6 · Tasks: 6.1–6.2 · Base: 4098a7a -->

Emmz's answers on page shape, caps across result sets, and bigint are in `20261025-1816-decision-paging-shape.md`.

What landed (in `src/SqlMcp/Execution/`):
- **`BufferedResult.cs`:**
  - `ResultColumn(Name, SqlType)`;
  - `ResultSet(Columns, Rows)`, where each row is a `JsonNode?[]` aligned with the columns, and null means SQL
    NULL;
  - `BufferedResult(ResultSets, Truncated, TruncationMessage)`, plus `RowCount`;
  - `ResultPage(ResultSetIndex, Columns, FirstRow, LastRow, Rows, PageNumber, PageCount, Handle)`, plus
    `IsLastPage`. Row numbers are 1-based within the set, and an empty set gives `0, 0`.
- **`ResultStore(TimeProvider)`:**
  - `Open(result, pageSize)` returns the first page, and issues a handle only if more pages remain.
    `NextPage(handle)` returns `ResultPage?`, and null means unknown or expired. `Abandon(handle)` returns bool.
    `Dispose()` runs at session end.
  - `UnknownHandleMessage` is the agent-facing text for §7. `IdleTimeout` is a fixed 10 minutes.
  - Handles are 16 random bytes in base64url. A timer sweeps every minute, and expiry is also checked on every
    access.
- **`IQueryExecutor.ExecuteAsync(connectionString, sql, EffectiveLimits, ct)`** returns `QueryOutcome`:
  - `QuerySucceeded(Result, Duration)`;
  - `QueryFailed(Kind, Message, ErrorNumber, Severity, State, Duration)`. `Kind` is the audit `FailureKind`, and
    **`Message` is for the agent only**: never audit it.
- **`SqlServer/SqlServerQueryExecutor`:** follows D7. It cancels the command when a cap is hit, then rolls back in
  `finally`. A timeout (`SqlException.Number == -2`) becomes `FailureKind.Timeout`, with a message that gives the
  limit. A failure to open is `Connection`.
- **`SqlServer/SqlServerValues`:** reads each column according to the result set's schema:
  - type names carry their length, precision or scale (`decimal(38,10)`, `nvarchar(50)`, `varbinary(max)`,
    `datetime2(7)`);
  - CLR UDTs are written as `"<type> (CLR type: serialised bytes, base64)"`;
  - SQL Server 2025 `json` is a string, and `vector` is a JSON array of numbers.

Decisions of my own (not product questions):
- **The connection opens with `Pooling=false`.** With pooling, a "closed" connection keeps its server session in
  the pool, so the spec's "connection released before paging" would be false. Without pooling, the session ends
  when the call does. The test checks `sys.dm_exec_sessions` for the call's own `@@SPID`. This also makes a failed
  rollback safe, because closing the connection rolls back on the server. The cost is a new connection per call,
  which is fine for agent traffic.
- **The byte cap counts each value's JSON text** with the default (escaping) encoder, plus 4 bytes for a NULL.
  Non-ASCII text therefore counts more than its raw UTF-8 size, which errs towards a smaller buffer.
- I read values with typed getters (`GetSqlDecimal`, `GetDateTime`, and so on) rather than generic
  `GetFieldValue<T>`. `decimal(38,…)` overflows `System.Decimal`, so `SqlDecimal` is what keeps every digit.
