# §7 MCP server and tools done

<!-- Section: 7 · Tasks: 7.1–7.3 · Base: 72753f4 -->

Start-up answers (pooling stays off, a bad config is reported by the tools, `list_databases` is always offered)
are in `20261025-1835-decision-serve-startup.md`.

Emmz's answers to the pre-commit questions, all confirming what was built:
- **If the `executed` audit write fails, the rows are withheld.** The agent gets `AuditLog.UnavailableMessage`
  instead of the result. Fail closed.
- **Unknown identifiers and unavailable databases are not audited**, following D8's diagram. Only permission
  denials, classifier rejections, executions and failures are logged.
- **A query the client cancels is logged as `failed` with kind `other`**, then the cancellation propagates.
  `FailureKind` gets no new value.
- **The response shape stays as built:**
  - fields are snake_case, and rows are arrays aligned with `columns`;
  - `result_sets`, `rows_buffered`, `truncated` and `truncation_message` appear on the first page only;
  - `handle` appears only while more pages remain, and `last_page` marks the end.

What landed:
- **`Mcp/SqlMcpSession`:** loaded once per `serve`. It holds the version, the existing config files,
  `Databases`, `ConfigError` (a `ConfigException` is caught and turned into agent-facing text), the audit log, the
  `ResultStore`, and `Engines` (`Engine` → `EngineServices(Classifier, Executor)`). The project file counts as
  approved through `ApprovalStore.IsApproved`. `Dispose` releases the store and the audit log.
- **`Mcp/ToolPipeline`:** runs D8's order and returns a `ToolResult(IsError, Text)`.
  - It has `ListDatabases`, `QueryAsync`, `NextPage` and `Abandon`.
  - The denial text is `"<group> is denied on <id> (source: <source>)."`, followed by `GroupGrant.Reason` (the
    `ApprovalMessages` wording) when unapproved.
  - A rejection is `"Rejected, nothing was sent to the database: <verdict reason>"`.
  - `NextPage` and `Abandon` check only that the audit log is available, not the config.
- **`Mcp/ToolResponses`:** the JSON records, and `ToolResult.Json`: snake_case, nulls left out, relaxed escaping.
  `DatabaseInfo.NotApproved` lists every ignored widening, including raised limits.
- **`Mcp/ToolCatalog`:**
  - `ToolDescriptions` holds the guidance text, and `Query(databases)` appends the default caps, plus any database
    whose limits differ.
  - `ToolCatalog.Build` always offers `list_databases`, and adds `query`, `next_page` and `abandon` only if some
    database allows `query`. The tools are created with `McpServerTool.Create(MethodInfo, target, options)`,
    annotated read-only.
  - `SqlMcpTools` wraps each result in a `CallToolResult`.
- **`Cli/ServeCommand`:**
  - It runs System.CommandLine `serve [--project]` on a Generic Host, with the console logger sent to stderr at
    every level. The content root is `AppContext.BaseDirectory`.
  - It writes `session_start` before `RunAsync` and `session_end` in a `finally`, and logs the audit path or
    problem, and any config error, to stderr.
  - `Program.cs` has the root command. §8 adds the rest.
- **`Execution/ByteSize.Format`:** shared by the truncation message and the tool description.

Tests:
- **Unit:** `Mcp/ToolPipelineTests` (19) and `Mcp/ToolCatalogTests` (6), using `SessionBuilder`: temp HOME and
  project directories, the real classifier, `FakeExecutor` with a `Cancels` flag, and `Events(session)` to read the
  audit log.
- **Integration:** `Mcp/ServeTests` (4) runs `dotnet SqlMcp.dll serve --project <temp>` with `HOME` set to a temp
  directory. It covers:
  - "Started by a client";
  - "Successful query", checking the executed event and that no row values or password appear in the log;
  - "Rejected statement", checking the denied event and that no executed event appears;
  - a raw-stdio test: every stdout line is JSON-RPC, closing stdin exits 0, and the log holds `session_start` then
    `session_end`.

Gotchas:
- The audit file is held open by the server, so tests read it with `FileShare.ReadWrite`.
- `McpClient.ServerInfo` is nullable, and xUnit's analyzer wants `TestContext.Current.CancellationToken` passed to
  `File.ReadAllTextAsync` and similar calls.
- `ModelContextProtocol` 2.3.0 wasn't in the local NuGet cache, so the first restore had to run unsandboxed.

Deferred nit: the rejection reason for a command says "use the command tool", but that tool doesn't exist until the
`write-tools` change. That's acceptable: the agent learns why it was refused.
