# §4 Statement classification done

<!-- Section: 4 · Tasks: 4.1–4.6 · Base: 00e8ede -->

The scope and table-hint policy (Emmz's answer) are in `20261025-1757-decision-classifier-scope.md`.

What landed:
- **`Classification/IStatementClassifier.cs`:** `StatementCategory`, `StatementClassification`,
  `ClassificationResult` (with `BatchError` for parse, GO and empty) and `ForTool(category)` → `BatchVerdict`.
  The single-statement wrong-tool reason is exactly `classified as command; use the command tool`.
- **`Classification/SqlServer/`:**
  - `SqlServerStatementClassifier` (`TSql170Parser`);
  - `Allowlists` (the statement → category map plus a set of node types per category);
  - `SideEffectChecks` (SELECT INTO, table hint kinds, EXEC of a string, a variable, `AT` a linked server,
    `OPENDATASOURCE`, `sp_executesql`);
  - `Phrases`, the readable names.
- **Tests:** `ClassifierTable` (accepted and rejected rows as data), `ClassifierTests` (batch, GO, syntax and
  wrong-tool scenarios) and `AllowlistGuardTests`, which lists types that must never be on the query allowlist.
- **`docs/classifier.md`:** how the classifier works, and the steps for allowing a node type.

How the allowlists were built: a throwaway probe listed every node type that the table's accepted rows use, by
category. I reviewed each type for safety before adding it, then deleted the probe. `TSqlScript`/`TSqlBatch` are
not listed, because the visitor starts at each statement.

Decisions and gotchas:
- **Any `GO` token rejects the batch**, even a single trailing one. That is stricter than "more than one batch",
  but SqlClient would fail on it anyway.
- **`EXEC dbo.p AT lnk` doesn't parse.** `AT` only follows a string. For `EXEC ('…') AT lnk`, the
  `ExecuteSpecification` is visited before the string, so the reason is the linked-server one.
- **The table carries category names as strings.** xUnit theory parameters on public methods can't use the
  internal `StatementCategory`.
- `TheoryDataRow<T1, T2>` in xunit.v3 exposes `.Data` (a tuple); `GetData()` is not public.

Self-review against the classification spec: every scenario is a row or a test. The allowlists for command, ddl
and execute are deliberately basic; `write-tools` grows them.
