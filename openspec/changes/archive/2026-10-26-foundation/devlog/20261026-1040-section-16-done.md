# §16 Review fixes: cleanup — done

<!-- Section: 16 · Tasks: 16.1–16.4 · Base: 660f65f -->

What landed:
- **16.1.** `ApprovalStore.Approve` writes through `AtomicFile.WriteAllText`. Its own temp-and-move is gone, along
  with the `Directory.CreateDirectory`, which `AtomicFile` already does. As a side effect, a failed write no longer
  leaves `approvals.json.<guid>.tmp` behind: `AtomicFile` deletes its temp file in `finally`, and names it as a
  hidden file.
- **16.2.** `AtomicFile` resolves a link at the path to its final target with `ResolveLinkTarget(returnFinalTarget:
  true)`. It writes the temp file and does the rename beside that target, so the link survives.
  - A dangling link writes the file it points at.
  - Only a link on the file itself is resolved. Directory links don't matter for the rename. Emmz chose this over
    resolving the full path with `ApprovalStore.CanonicalPath`.
  - Tests: `Edit_through_a_symbolic_link_writes_the_target_and_keeps_the_link` (config editor) and
    `Approving_through_a_linked_store_keeps_the_link` (approval store).
- **16.3.** On Windows, `LaunchCommand.IsOnPath` calls `ProgramLookup.Resolve(program, PATH, PATHEXT, File.Exists)`
  and counts a changed result as found. Elsewhere it keeps the plain `dir/program` check.
  - **Behaviour change, agreed with Emmz:** on Windows, a bare extensionless `sql-mcp` no longer counts as on PATH.
    That matches what the shell, and `SystemProcessRunner` through `ProgramLookup`, would actually start.
  - `CliRunner.IsWindows` is now settable (it was hard-coded `false`).
  - Test: `On_windows_sql_mcp_is_on_path_only_with_a_PATHEXT_extension`, a theory over `PATH="a;b"` and
    `PATHEXT=".BAT"`. `sql-mcp.bat` gives the tool launcher, and a bare `sql-mcp` gives dnx. The old code missed
    `.bat` and split PATH on `:` on the macOS and Linux test hosts.
- **16.4.** `tests/SqlMcp.Tests/PlaceholderTests.cs` is deleted.

Gotcha: the config editor writes a property it adds to a one-line file in compact form (`"allow":["query"]`), so
assertions about the text have to match that.

Self-review: the specs, design.md and the ADRs say nothing about symlinks, atomic writes or PATHEXT, so nothing
drifted. There's no dead code left: `AtomicFile` is now the only temp-and-rename writer.
