# §3 Permissions, layering and approval done

<!-- Section: 3 · Tasks: 3.1–3.2 · Base: 4e8f8e4 -->

Emmz's answer, that the user file owns the connection string, is in `20261025-1746-decision-connection-string-owner.md`.

What landed (in `src/SqlMcp/Permissions/`):
- `PermissionResolver.Resolve(user, project, projectApproved)` → `EffectiveDatabase` list (user entries first,
  then project-only ones). Each has `Groups` (a `GroupGrant` per group: `Allowed`, `Source`, and a `Reason` when an
  unapproved grant was ignored), `Limits` (`EffectiveLimits`, D7 defaults), `UnapprovedWidenings` (for example
  `grants ddl` or `raises timeoutSeconds`, the diff that §8.4 `approve` will show) and `DefinedIn`.
- `ApprovalStore(path, TimeProvider)`: `IsApproved(configPath, sha256)` and `Approve(...)`, written atomically
  (temp file then rename). `ApprovalStore.CanonicalPath` resolves symbolic links segment by segment, because
  macOS temp dirs sit under `/var` → `/private/var`. A test covers this.
- `ApprovalMessages.NotApproved/Grants/Raises/AskTheUser` is the single wording. §7 tools and §8 CLI warnings
  **must** use it.
- `ConfigFile` now carries `Sha256` of the file's exact bytes. `Load` hashes the bytes. `Parse(text)` hashes
  the UTF-8 text and is meant for tests.

Decisions:
- **The project layer is computed in full, then split.** Each group is judged against its state *before* the
  project layer. A project re-allowing something the user already allows is not a widening. A project that
  denies and then allows a group that was denied before is still a widening.
- **Limits work field by field.** A lower value always applies. A higher one keeps the pre-project value unless
  the file is approved.
- **Project defaults apply to every database**, including ones only the user file defines (D4's chain). So a
  project can narrow user databases.
- **A damaged `approvals.json` fails closed.** Nothing counts as approved, and `Approve` refuses to overwrite it,
  with an error naming the file.
- **Unparseable entries** (`(invalid)`) are keyed by file and location in the resolver, so they are never merged.
