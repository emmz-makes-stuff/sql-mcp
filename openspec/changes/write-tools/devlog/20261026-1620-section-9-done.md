# §9 done: ddl batches (review fixes)

<!-- Base d3d84f4 · gates green -->

Where it came from: the whole-change review (`git diff 49514d9..HEAD`) found two things:
1. A view or schema statement with another statement in the batch fails.
2. `ddl`'s description promised result sets and paging.

**Correction to the review.** On a throwaway container, raw `sqlcmd` showed Msg 111 ("'CREATE VIEW' must be the
first statement in a query batch"), and the same for `CREATE SCHEMA`. I first planned 9.1 as a new pre-send
refusal. Building it showed that ScriptDom already refuses all six batch shapes as syntax errors, so nothing was
ever sent, and the new check could never run. I reverted that and asked again.
- Emmz's ruling: keep the refusal as it is, but add a hint to the syntax error. tasks.md 9.1 is reworded to
  match what landed.

What landed:
- **`SqlServerStatementClassifier.OwnCallHint`:** only runs when the parse fails.
  - It re-tokenizes with `GetTokenStream`, because `Parse` may return no usable fragment on errors.
  - It drops whitespace, comments, semicolons and EOF, and looks for CREATE VIEW, ALTER VIEW, CREATE OR ALTER
    VIEW or CREATE SCHEMA.
  - It hints when something comes before that statement, or when a parse error sits on a later CREATE, ALTER,
    DROP or TRUNCATE token.
  - The batch error becomes "`<STATEMENT>` must be the only statement in its call: send it on its own. The parser
    reported: syntax error at …".
  - A lone malformed view (`CREATE VIEW … AS SELEC …`) and a broken table followed by an index get no hint.
- **ToolCatalog:**
  - The shared `WriteGuidance` no longer ends with the returns sentence. `RowsGuidance` ("Returns committed:
    true and the rows each statement affected; any result sets are buffered and paged as for query.") is added
    to command and execute only.
  - ddl now ends "… must each be sent in a call of their own. … Returns committed: true." and then the cap
    sentence.
- **Docs:** a "View and schema statements go alone" bullet in `docs/classifier.md`'s ddl section, and one sentence
  in the README's ddl bullet.
- **Tests:**
  - `ClassifierTests`: the hint ×6, no hint ×2, and other ddl statements sharing a call.
  - `ToolCatalogTests.The_ddl_description_sends_views_and_schemas_alone_and_promises_no_rows`.
  - `ServeTests.Schema_table_and_view_through_ddl`: over stdio, the combined schema-and-table call is refused with
    the hint. Schema, table plus ALTER, and view then go through ddl one call each, and query reads the view. This
    is the first integration test to run a view or schema through ddl.
- Gotcha: ScriptDom accepts a trailing comma in a column list (`CREATE TABLE t (a int,)`), so it's no use as a
  syntax-error fixture.

Not changed: the delta spec has no scenario for the hint. It refines an existing refusal's wording, like §8.
