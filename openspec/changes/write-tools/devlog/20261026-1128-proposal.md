# write-tools proposed

<!-- Planning only · HEAD before this commit: 4a9b19b (main, foundation merged) · nothing built yet -->

Proposal, specs (write-execution new; statement-classification, permissions and audit-log modified), design
(W1–W8) and tasks (§1–§7, 23 tasks) are written. `openspec validate write-tools --strict` is valid.

Emmz's answers (2026-10-26), all of them the recommended option except where noted:
- **Commit model:** one transaction per call, all or nothing. A preview-then-confirm step and autocommit were both
  rejected.
- **DML guards:** the affected-rows cap (`maxAffectedRows`, default 1000) **and** the WHERE rule for UPDATE and
  DELETE. She picked both, where only the cap was recommended.
- **DDL scope:** declarative objects only. Procedures, functions and triggers are refused, because their bodies run
  later, unseen by the classifier.
- **Results:** rows affected plus result sets (OUTPUT, procedure SELECTs), through the query buffer and paging.
- **Execute:** user procedures only. No `sys` schema, and no names starting `sp_` or `xp_`.
- **Names:** writes stay in the target database. Three- and four-part names are refused for command, ddl and
  execute only. Queries are unchanged (a follow-up idea is in `tasks.md`).
- **Side-agent note: the cap undoes an oversized change but doesn't prevent it.** Emmz chose to document it, not
  to add a separate write timeout. The documentation is design.md Risks, tasks 6.4 (tool descriptions: count with
  `query` first) and 6.5 (README: short `timeoutSeconds` where command is allowed). A `writeTimeoutSeconds` limit
  was offered and declined.

Things the plan relies on that a build must not lose:
- A capped result from a write must **drain, not cancel**, or the cancel aborts the write (W3).
- `SET XACT_ABORT ON` is issued by the executor before every write batch (W2). The classifier rejects `SET`, so
  agents can't undo it.
- The REMOVED + ADDED pair in the statement-classification delta is deliberate. OpenSpec refuses to drop the
  "No tool for that category yet" scenario through MODIFIED.

Gotchas from foundation that apply here:
- Name test files exactly as the code looks them up. CI's Linux filesystem is case-sensitive and macOS isn't (see
  the PATHEXT test fix, 2555bdd).
- `make validate` fails with "no active change" when no change is open. That's the Makefile, not the specs.
- After a sandboxed build, run `dotnet build-server shutdown` before `make gates`.
